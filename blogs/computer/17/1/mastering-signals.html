Mastering Angular Signals

Reactive Harmony: Building a Glitch-Free Shopping Cart

The Signal Revolution

Angular Signals are not just a new feature; they are a paradigm shift. They allow us to move away from the "magic" of Zone.js and towards explicit, fine-grained reactivity. Unlike RxJS Observables, which are streams of values over time, Signals are holders of a value that notify interested consumers when that value changes.

In this deep dive, we aren't just looking at the syntax. We're going to build a fully reactive Shopping Cart to demonstrate the power of computed() signals and structured state management.

The Concepts: Writable vs. Computed

Before we code, let's clarify the tools in our belt:

  • Writable Signals (signal()): The source of truth. You can set or update these directly.
  • Computed Signals (computed()): Derived state. These update only when their dependencies change. They are read-only and memoized.
  • Effects (effect()): Side effects that run when signals change (e.g., logging, syncing to localStorage).

Walkthrough: The Reactive Shopping Cart

We want to build a cart where:
1. We have a list of products.
2. We can add products to a cart.
3. The Total Price, Item Count, and Tax are calculated automatically.
4. No manual subscription management!

Step 1: Defining the Interfaces

export interface Product {
  id: number;
  name: string;
  price: number;
}

export interface CartItem {
  product: Product;
  quantity: number;
}

Step 2: The Shopping Cart Service

We'll encapsulate our logic in a service. This is where Signals shine by keeping our state clean.

import { Injectable, signal, computed } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class CartService {
  // 1. The Source of Truth
  private items = signal<CartItem[]>([]);

  // 2. Computed Values (Derived State)
  
  // Calculate total number of items
  totalItems = computed(() => 
    this.items().reduce((acc, item) => acc + item.quantity, 0)
  );

  // Calculate subtotal
  subTotal = computed(() => 
    this.items().reduce((acc, item) => 
      acc + (item.product.price * item.quantity), 0)
  );

  // Calculate Tax (e.g., 10%)
  tax = computed(() => this.subTotal() * 0.1);

  // Calculate Final Total
  totalPrice = computed(() => this.subTotal() + this.tax());

  // 3. Actions (Mutating State)
  addToCart(product: Product) {
    this.items.update(currentItems => {
      const existingItem = currentItems.find(i => i.product.id === product.id);
      
      if (existingItem) {
        // Immutable update pattern
        return currentItems.map(i => 
          i.product.id === product.id 
            ? { ...i, quantity: i.quantity + 1 } 
            : i
        );
      } else {
        return [...currentItems, { product, quantity: 1 }];
      }
    });
  }

  removeFromCart(productId: number) {
    this.items.update(items => 
      items.filter(i => i.product.id !== productId)
    );
  }
  
  // Expose items as ReadOnly for external consumption if needed
  cartItems = this.items.asReadonly();
}

Step 3: The Component (The Consumer)

Now, let's see how simple the component logic becomes. No ngOnChanges, no subscribe(). 

import { Component, inject } from '@angular/core';
import { CartService } from './cart.service';
import { CurrencyPipe } from '@angular/common';

@Component({
  selector: 'app-shopping-cart',
  standalone: true,
  imports: [CurrencyPipe],
  template: `
    <div class="cart-display">
      <h2>Your Cart (<span>{{ cart.totalItems() }}</span>)</h2>
      
      @for (item of cart.cartItems(); track item.product.id) {
        <div class="item-row">
           {{ item.product.name }} x {{ item.quantity }}
           <button (click)="cart.removeFromCart(item.product.id)">Remove</button>
        </div>
      } @empty {
        <p>Your cart is empty.</p>
      }

      <div class="summary">
        <p>Subtotal: {{ cart.subTotal() | currency }}</p>
        <p>Tax: {{ cart.tax() | currency }}</p>
        <h3>Total: {{ cart.totalPrice() | currency }}</h3>
      </div>
    </div>
  `
})
export class ShoppingCartComponent {
  protected cart = inject(CartService);
}

Why This is Better

1. Performance: Angular knows exactly which text node to update. If cart.tax() changes, ONLY that specific DOM element updates.
2. Readability: The dependency graph is clear. totalPrice depends on subTotal and tax. You can't accidentally get an "out of sync" total because it's mathematically derived.
3. Less Boilerplate: We didn't import BehaviorSubject, Observable, scan, or `map`.

Conclusion

Signals bring a level of developer ergonomics to Angular that rivals React's Hooks or Vue's Composition API, but with Angular's specific flavor of structural discipline. Start moving your local component state to Signals today!
