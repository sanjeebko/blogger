Angular's New Control Flow

Cleaner Syntax, Better Types, and Superior Performance

Say Goodbye to Structural Directives

For years, we've relied on *ngIf, *ngFor, and *ngSwitch. While they served us well, they were technically "directives" hacked to look like syntax. They had limitations in type-checking and required importing CommonModule or NgIf/NgFor in standalone components.

Angular 17 introduces a new, built-in control flow syntax. It's not a directive; it's part of the template language itself.

Old (*ngIf) New (@if)
Requires Imports (CommonModule) Built-in (No imports needed)
Template based (extra <ng-template> for else) Javascript-like syntax ({ })
Slower (runtime directive overhead) Faster (compiled directly)

The New Syntax: A Walkthrough

1. Conditional Rendering (@if)

The syntax is cleaner and supports @else if naturally.

@if (user.isLoggedIn) {
  <user-dashboard [user]="user" />
} @else if (user.isGuest) {
  <guest-banner />
} @else {
  <login-form />
}

2. The Power of Loops (@for)

The new @for block mandates a track expression. This forces developers to adopt the high-performance practice of keyed lists, ensuring that Angular knows exactly which items changed, moved, or were deleted. 

@for (product of products; track product.id) {
  <product-card [data]="product" />
} @empty {
  <div class="no-results">No products found.</div>
}

Notice the @empty block? It covers the common use case of "show this list, or show a message if empty" without needing a separate wrapper check!

Building a Dynamic User Dashboard

Let's build a real-world example: A filterable user list. We want to show how @for interacts with Signals and how it handles updates efficiently.

Step 1: The Code (Standalone Component)

import { Component, signal, computed } from '@angular/core';

interface User {
  id: number;
  name: string;
  role: 'admin' | 'user';
}

@Component({
  selector: 'app-user-list',
  standalone: true,
  template: `
    <div class="controls">
      <button (click)="filter.set('all')">All</button>
      <button (click)="filter.set('admin')">Admins Only</button>
      <button (click)="shuffle()">Shuffle List</button>
    </div>

    <ul class="user-grid">
      @for (user of filteredUsers(); track user.id; let idx = $index, e = $even) {
        <li [class.gray-bg]="e">
          <span class="index">{{ idx + 1 }}.</span> 
          <strong>{{ user.name }}</strong> 
          <span class="badge">{{ user.role }}</span>
        </li>
      } @empty {
        <li>No users match your filter.</li>
      }
    </ul>
  `,
  styles: [`
    .user-grid { list-style: none; padding: 0; }
    .user-grid li { padding: 10px; border-bottom: 1px solid #eee; display: flex; gap: 10px; }
    .gray-bg { background: #f9f9f9; }
    .badge { background: #e3f2fd; padding: 2px 8px; border-radius: 12px; font-size: 0.8em; }
  `]
})
export class UserListComponent {
  users = signal<User[]>([
    { id: 1, name: 'Alice', role: 'admin' },
    { id: 2, name: 'Bob', role: 'user' },
    { id: 3, name: 'Charlie', role: 'user' },
    { id: 4, name: 'David', role: 'admin' },
  ]);

  filter = signal<'all' | 'admin'>('all');

  filteredUsers = computed(() => {
    const f = this.filter();
    return f === 'all' 
      ? this.users() 
      : this.users().filter(u => u.role === 'admin');
  });

  shuffle() {
    this.users.update(list => [...list].sort(() => Math.random() - 0.5));
  }
}

Why track is Critical

In the example above, track user.id tells Angular that the unique identity of each row is the User ID. If we shuffle the list, Angular moves the DOM elements instead of destroying and recreating them. This preserves internal state (like focus or text selection) and is significantly faster for large lists.

Automatic Migration

Worried about rewriting all your existing templates? Don't be. The Angular team provided a schematic to do it for you! 

ng generate @angular/core:control-flow

Running this command will scan your project and automatically convert *ngIf to @if, *ngFor to @for, and so on. It's safe, fast, and magical.

Conclusion

The new control flow syntax is a massive quality-of-life improvement. It makes templates more readable, safer, and faster by default. Combined with Signals, it completes the picture of the "New Angular" — a framework that is both powerful and developer-friendly.
