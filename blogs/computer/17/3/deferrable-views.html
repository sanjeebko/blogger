Deferrable Views (@defer)

Lazy Loading Made Easy, Granular, and Native

The Cost of "Everything at Once"

In Single Page Applications (SPAs), bundle size is the enemy. Historically, we fought this with Route-based Lazy Loading. We'd split our app into feature modules (Admin, User, Settings) and load them only when the user navigated there.

But what about the Landing Page? It might have a heavy Google Map, a complex Chart, and a Video Player. Loading all of that upfront hurts your Core Web Vitals (specifically LCP and TBT), even if the user never scrolls down to see them.

Enter @defer. It allows you to lazy load parts of a template with zero boilerplate. No extra `NgModule`, no route config. Just pure magic.

The Syntax: Declarative Loading

The @defer block controls when the dependency is fetched. It works in tandem with @placeholder, @loading, and @error blocks to provide a complete UX. 

@defer {
  <heavy-chart-component />
} @placeholder (minimum 500ms) {
  <div class="chart-skeleton"></div>
} @loading (after 100ms; minimum 1s) {
  <spinner />
} @error {
  <p>Failed to load the chart.</p>
}
  • @defer: Main content to be lazy-loaded.
  • @placeholder: Shown immediately until the bundle is fetched. Crucial for preventing layout shift (CLS).
  • @loading: Optional state shown while fetching (if it takes too long).
  • @error: Shown if the network request fails.

Triggers: You Control the "When"

The real power lies in the triggers. You can specify exactly what user action or state should initiate the download.

1. on viewport (Standard)

Load when the placeholder enters the visible screen area.

@defer (on viewport) { 
  <app-footer /> 
}

2. on interaction (User-driven)

Load when the user clicks or touches the placeholder area.

@defer (on interaction) { 
  <app-comments-section /> 
} @placeholder {
  <button>Load Comments</button>
}

3. on hover (Predictive)

Load when the user mouses over an area. Great for tooltips or heavy dropdowns.

@defer (on hover) { 
  <app-tooltip-content /> 
}

4. on timer (Delayed)

Load after X seconds. Good for low-priority tracking scripts or ads.

@defer (on timer(5s)) { 
  <app-analytics-widget /> 
}

Real World Example: The "Heavy" Gallery

Imagine a photo gallery where clicking an image opens a high-res editor/viewer that weighs 2MB.

@Component({
  selector: 'app-gallery',
  standalone: true,
  imports: [ImageThumbnailComponent, HighResEditorComponent], // No lazy import syntax needed!
  template: `
    <div class="grid">
      @for (img of images; track img.id) {
        <app-thumbnail [src]="img.src" (click)="selectedId.set(img.id)" />
      }
    </div>

    // Only load the editor when an image is actually selected
    @defer (when selectedId() !== null) {
      <app-high-res-editor [imageId]="selectedId()" />
    } @placeholder {
      <!-- invisible or empty placeholder -->
    }
  `
})
export class GalleryComponent {
  selectedId = signal<number | null>(null);
  images = [...]; 
}

In this example, the HighResEditorComponent code is split into a separate chunk automatically by the compiler. The browser won't download it until selectedId becomes non-null.

Prefetching

You can also decouple the "loading" from the "rendering". Maybe you want to load the code on idle, but only render it on interaction. 

@defer (on interaction; prefetch on idle) { 
  <app-heavy-widget /> 
}

Conclusion

@defer is a game-changer for Core Web Vitals. It puts performance optimization directly into the template syntax where it belongs, making it intuitive and easy to maintain. Start using it for any component that isn't critical for the initial paint!
