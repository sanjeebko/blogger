SSR & Hydration

The End of the "White Screen of Death"

What is Hydration?

In the old days of Angular Universal (SSR), the server would render the HTML string and send it to the browser. The user would see the content quickly, but moments later, the client-side Angular application would boot up, destroy the existing DOM, and re-render the entire page from scratch.

This caused a dreaded "flicker" and was inefficient. Non-Destructive Hydration solves this. Angular now reuses the DOM nodes created by the server, merely attaching event listeners and internal state to them. It's seamless and instant.

Old SSR

Server HTML -> 👁️ Visible -> 💥 Destroy -> 🏗️ Rebuilt

New Hydration

Server HTML -> 👁️ Visible -> 💧 Hydrate (Attach Events)

Enabling Hydration

If you're starting a new app with `ng new`, it's on by default. For existing apps, it's just a provider away.

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideClientHydration } from '@angular/platform-browser';

export const appConfig: ApplicationConfig = {
  providers: [
    provideClientHydration()
  ]
};

Handling Third-Party Scripts (The "Skip" Attribute)

Sometimes, you might use a legacy jQuery plugin or a library that manipulates the DOM directly, confusing Angular's hydration engine. You can tell Angular to skip hydration for that specific component or element. 

// In your template
<div ngSkipHydration>
  <!-- Content manipulated by external JS -->
  <div id="legacy-slider"></div>
</div>

SSG vs. SSR

With Angular's new builder, you can choose your rendering strategy easily.

Server-Side Rendering (SSR)

The page is built on request. Good for dynamic data (e.g., User Dashboards, Search Results).

Static Site Generation (SSG)

The page is built at build time. Good for static content (e.g., Blogs, Documentation, Marketing Pages).

To enable SSG (Prerendering), you simply configure your `angular.json` or use the new command line flags to specify which routes to prerender.

Conclusion

Hydration is the final piece of the puzzle for Angular to become a top-tier framework for public-facing websites, not just enterprise dashboards. With excellent SEO, fast Core Web Vitals, and no flicker, there's no reason not to use it.
